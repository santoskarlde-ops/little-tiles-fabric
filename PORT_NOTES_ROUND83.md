# Round 83 — chunk layers move from RenderType to ChunkSectionLayer (uncompiled)

Paste this entry at the top of PORT_NOTES.md (separate file so no notes are overwritten).

- Round 82 result (build_dbefe9.log vs build_d57623.log): 553 -> 536 errors, all 17 targeted locations gone, none new.
- Evidence for this round: `mc-api-r83.txt` (javap of the 26.3 jar). `ChunkSectionLayer` is an enum with only SOLID, CUTOUT and TRANSLUCENT; `RenderType` has no `solid()/cutout()/cutoutMipped()/translucent()/tripwire()` and no `CHUNK_BUFFER_LAYERS`; those moved to `RenderTypes` (entity/gui types only). javac in the Round 82 log already complained `Entry<ChunkSectionLayer,MeshData>` cannot be converted to `Entry<RenderType,...>` and `RenderType cannot be converted to ChunkSectionLayer`, so vanilla's section compiler and buffer pack already use `ChunkSectionLayer` as the layer key.
- Change: every place that used `RenderType` as a *chunk layer key* now uses `ChunkSectionLayer` (29 files): `ChunkLayerMap`, `ChunkLayerMapList`, `BlockBufferCache`, `IBlockBufferCache`, `LayeredBufferCache`, `AdditionalBuffers`, `LittleRenderPipelineType`, `LittleRenderPipelineForge`, `LevelTransition`, `StructureBlockToEntityPacket`, `RenderChunkExtender`, `LittleRenderChunk`, `LittleAnimationRenderManager`, `LittleLevelRenderManager`, `LittleEntityRenderManager`, `SectionCompilerResultsExtender`, `RenderingThread`, `IParentCollection`, `LittleTile`, `LittleBlock`, `ILittleMCBlock`, `LittleMCBlock`, `LittleMissingBlock`, `LittleItemHolder`, `LittleSignalCableBase`, `LittleSignalDisplay`, `GuiAnimationViewerStorage`, `LittleBlockClientRegistry`, the `ChunkRenderTypeSet` stub, and the layer code in `LittleAnimationHandlerClient`. `RenderType.CHUNK_BUFFER_LAYERS` is now `ChunkSectionLayer.values()`; `solid()/cutout()/translucent()` are `SOLID/CUTOUT/TRANSLUCENT`.
- Behaviour decisions: `cutoutMipped()` maps to `CUTOUT` and `tripwire` has no layer any more. `LittleAnimationHandlerClient.renderChunkLayer` therefore no longer handles the cutout-mipped and tripwire stages (they would only draw cutout twice), and `GuiAnimationViewerStorage` draws SOLID, CUTOUT, TRANSLUCENT once each; the mipmap-blur workaround around the old mipped pass is removed with it. Blocks that relied on a tripwire layer have no matching layer yet.
- Not changed on purpose: `LittleRenderBoxItem.getBakedQuad` (overrides a CreativeCore method I cannot see), `ItemRenderCache` (passes `RenderType` to CreativeCore's box-item layer), `RenderType.lines()` calls in `PreviewManager` and `LittleAnimationHandlerClient` (now `RenderTypes.lines()`, but the buffer-source chain around them is still unported), and everything under `mixin/` and `client/mod/` (excluded from the build; they still say `RenderType` and need the same change before they are re-enabled).
- Source-reviewed only; every changed file parsed with the JDK compiler (no syntax errors). Expected: about 34 locations removed (all `RenderType.solid/cutout/cutoutMipped/translucent/tripwire`, `CHUNK_BUFFER_LAYERS` and `TRANSLUCENT` errors in the files above, plus the two incompatible-type errors). No new count is claimed; new errors would mean a call I could not see passes a `RenderType` into a layer parameter.
