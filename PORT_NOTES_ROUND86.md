# Round 86 — GUI viewers on GuiGraphicsExtractor, RenderTypes.lines, block-entity bounds (uncompiled)

Apply after Round 85. Paste this entry at the top of PORT_NOTES.md.

- `GuiAnimationViewer`, `GuiIsoAnimationViewer`: `GuiGraphics` no longer exists; its 26.3 replacement is `GuiGraphicsExtractor`. Evidence: the other client GUI classes in this tree (`GuiClientSignalController`, `GuiClientAdvancedTimelineChannel`, ...) already override `renderContent(GuiGraphicsExtractor, ...)` and call `super.renderContent`, so CreativeCore's signature takes it. In `GuiIsoAnimationViewer` the axis-label overlay was moved to the 26.3 GUI API: `graphics.pose()` is a JOML `Matrix3x2fStack` (so `pushMatrix/popMatrix/translate(float, float)` replace `PoseStack` push/pop/translate), and `drawString(font, text, x, y, color)` is `text(font, text, x, y, color)` with int-cast coordinates (both in the GuiGraphicsExtractor dump). The arrow-icon drawing in the same block still uses `RenderSystem.setShaderTexture/setShaderColor`, `GuiRenderHelper` and `Icon.location()` and is still unported. Targets 6 type errors; the label code was silent before because its receiver type was unresolved, so a new error there would be a mismatch in my casts.
- `PreviewManager`, `LittleAnimationHandlerClient`: `RenderType.lines()` is now `RenderTypes.lines()` (in the RenderTypes dump). The `mc.renderBuffers()` / `getMultiBufferSource()` chains on the same lines are untouched. Targets 2 errors.
- `LittleEntityRenderManager.renderBlockEntity`: `BlockEntityRenderer.getRenderBoundingBox` no longer exists (it was a NeoForge extension), so the visibility test uses `new AABB(blockentity.getBlockPos())`, NeoForge's default. Renderers that returned a bigger box (beacons, signs with long text) can be culled too early until a replacement exists. Targets 1 error.
- Source-reviewed only; the five files parsed with the JDK compiler. Expected: about 9 locations removed. No new count is claimed.
