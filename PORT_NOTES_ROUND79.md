# Round 79 — event-stub shapes and vanilla enchantment power (uncompiled)

Paste this entry at the top of PORT_NOTES.md. It is a separate file so the overlay does not overwrite notes for rounds I could not see.

- Baseline: the supplied build.log (561 javac errors, 524 distinct file/line/message locations). I could rebuild only the Round 54 tree (src-round44 + overlays 45-54 from GitHub). 483 of the 524 logged source lines match that tree exactly; the other 41 are in `LittleAnimationHandlerClient`, `LittleVanillaInteractionHandlerClient`, `LittleInventory`, `LittleChunkSerializer` and `LittleTilesClient`, which differ from it. None of those five files is touched here. The handoff brief said Round 37/38; the repo and logs are far past that, so this is numbered 79 (the evidence zips reach Round 78). If your applied round differs, renumber.
- `BlockEvent.EntityPlaceEvent` added to the local event stub (constructor `BlockSnapshot, BlockState, Entity`; getters for each). Targets the `Placement` `cannot find symbol`. Like the other stubs it is never dispatched, so the area-protection check in `Placement` never cancels. Real Fabric dispatch is still to design.
- `LevelEvent` / `Load` / `Unload` stub: constructors taking a `LevelAccessor` (no-arg ones kept). Targets the `SubServerLevel` constructor mismatch.
- `ILittleMCBlock` / `LittleMCBlock`: `Block.getEnchantPowerBonus` no longer exists. The bonus is now `1` when the block state is in `BlockTags.ENCHANTMENT_POWER_PROVIDER`, else `0` (NeoForge's default). Modded blocks that overrode the old hook are no longer asked. `BlockTags.ENCHANTMENT_POWER_PROVIDER` is not in the repo's API dumps; other `BlockTags` constants in this tree do compile. If it fails, that is one error replacing two.
- Checked only by parsing the four files with the JDK compiler (no syntax errors). Source-reviewed, not compiled. No error-count change is claimed; the expected change is at most 4 locations of 524.
- Not changed, deliberately: about 90% of what remains is the 26.3 rendering rewrite (`MultiBufferSource`, `BakedModel`, `GuiGraphics`, `VertexBuffer`, `Tesselator`, `BufferUploader`, `RenderSystem` state calls, `RenderType.translucent()/solid()/cutout()/CHUNK_BUFFER_LAYERS`). The API dumps show these replaced by `SubmitNodeCollector`, `GuiGraphicsExtractor`, `ChunkSectionLayer` and `com.mojang.renderpearl`, not renamed. Also open: `LittleGuiUtils` item-handler capabilities (needs a Fabric Transfer API design), excluded mixin accessors and optional Sodium/Iris references.
