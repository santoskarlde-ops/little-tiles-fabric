## Verified facts (from real sources/logs)
- **Packets:** `NetworkFieldTypeClass.writeContent/readContent` take `RegistryFriendlyByteBuf`; `NetworkFieldType.write(T, Class, @Nullable Type, CreativeByteBuf, PacketFlow)` / `read(Class, @Nullable Type, CreativeByteBuf, PacketFlow)` and all static `NetworkFieldTypes.write/read/writeMany/readMany` take `CreativeByteBuf`. `registerAndCodec` builds a StreamCodec that passes a **plain** RegistryFriendlyByteBuf, so never cast. `CreativeByteBuf(ByteBuf, RegistryAccess, Connection)` extends RegistryFriendlyByteBuf; `.connection` is used only by CreativeCore's packet-in-packet types (NetworkFieldTypes ~737/752). `CreativePacket.execute/executeClient/executeServer/requiresClient/requiresServer`.
- **GUI registry:** `GuiClientRegistry.register(Class<T extends GuiControl>, Function<T, GuiClientControl>)`; lookup = exact class, then `registerSpecial` factories, then nearest registered superclass (reverse registration order). `GuiServerRegistry.register(...)` is exact-class only, unmatched controls get `null`. Controls get their dist in the `GuiControl` constructor via `parent.createDist(this)`; `GuiLayer.CLIENT/SERVER` decide which registry. So an LT control only needs a client class + `register(...)` if it overrides render/flow/mouse/getControlFormatting. ~13 LT files do (table in GUI_SPLIT_PLAN.md); `getControlFormatting()` now lives on `GuiClientControl`/`GuiClientLayer`.
- **GUI API:** every control takes `IGuiParent parent` first (`new GuiButton(this, "name", x -> ...)`); `GuiControl(parent, name)` only stores the parent; `GuiParent.add` registers it. `GuiLayer(boolean client, String name[, w, h])`. `GuiCreator` takes `BiFunction<CompoundTag, Player, GuiLayer>`. `GuiSyncHolder.GLOBAL.layer(id, TriFunction<Boolean, HolderLookup.Provider, CompoundTag, T>)`. `GuiFlow` is an abstract class (`STACK_X`, `FIT_X`, `STACK_Y`). Graphics type is `GuiGraphicsExtractor`; input events `net.minecraft.client.input.KeyEvent` / `MouseButtonEvent`. `GuiClientControl` has public `rect`, `enabled`, `visible`; client classes implement the control's nested `XDist` interface (`renderContent(GuiGraphicsExtractor, mouseX, mouseY)`, `flowX/flowY`, `mouseMoved`, `looseFocus`...).
- **Minecraft 26.x:** `BlockEntity`/`Entity` use `ValueInput`/`ValueOutput` (`loadAdditional(ValueInput)`, `addAdditionalSaveData(ValueOutput)`, `EntityType.create(ValueInput, Level, EntitySpawnRequest)`); `CompoundTag` getters return Optional (`getBooleanOr`, `getIntOr`, `getStringOr`, `getListOrEmpty`, `getCompoundOrEmpty` exist; `read(key, Codec)`/`store(key, Codec, value)`); `Level.isClientSide()` is a method; `ResourceLocation` is `Identifier`; `net.minecraft.util.Util`; `GuiGraphics` is `GuiGraphicsExtractor`; `BakedQuad` moved to `net.minecraft.client.resources.model.geometry`; `VertexFormat(Element)` moved to `com.mojang.renderpearl.api.vertex`; `BlockEntity.getUpdateTag(HolderLookup.Provider)` and `saveWithFullMetadata(provider)` still exist.
- **Fabric API** (26.1 javadoc, 0.144.3; recheck against 0.165.0+26.3): `PlayerBlockBreakEvents.{Before,After,Canceled}`, `AttackBlockCallback`, `AttackEntityCallback`, `UseBlockCallback`, `BlockEvents.{UseItemOnCallback,UseWithoutItemCallback}`, `ItemEvents.{UseCallback,UseOnCallback}`. Renderer API and Indigo are ported to 26.2+, so Phase 4 can use them.
- **Round-13 log classification of 306 "does not override" errors:** ~13 are GUI (above); the larger share are vanilla API changes: Level subclasses (`playSound`, `playSeededSound`, `levelEvent`, `getShade`, `getRecipeManager`), `Item` (`appendHoverText`, `canAttackBlock`), `Block` (`neighborChanged`, `codec`), chunk tickets (`addRegionTicket`, `removeRegionTicket`, `TicketType` no longer generic, `ServerChunkCache.level` private), entity save/load, packet listeners (`getConnection`, `disconnect`).

## Lessons from this port (avoid repeating)
- A `.gitignore` entry `build/` silently excluded `client/render/cache/build/` from every overlay for many rounds; it is now `/build/`. When building overlays, diff by content hash and check ignored directories.
- Do not compare my own "unique error" counts with older numbers; use javac's tally line. I once reported a "jump" from 2,771 to 5,426 that was a counting artifact.
- Do not change an override signature without checking the base class source: I briefly changed `writeContent` buffer types to `CreativeByteBuf` and reverted after seeing the base takes `RegistryFriendlyByteBuf`.
